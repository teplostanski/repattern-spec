# repattern Спецификация 1.0.0-beta.1 (JavaScript Flavor)

Встраиваемый data-first DSL для построения JavaScript RegExp из декларативных сериализуемых схем.

**Языки:** [Английский](/)

**Участие:** GitHub [teplostanski/repattern-spec](https://github.com/teplostanski/repattern-spec) ([создать issue](https://github.com/teplostanski/repattern-spec/issues/new), [открытые issues](https://github.com/teplostanski/repattern-spec/issues))

**Версии:** current (эта страница), [1.0.0-beta.0](/ru/1.0.0-beta.0/)

## Аннотация

Спецификация repattern описывает [встраиваемый DSL](https://ru.wikipedia.org/wiki/%D0%9F%D1%80%D0%B5%D0%B4%D0%BC%D0%B5%D1%82%D0%BD%D0%BE-%D0%BE%D1%80%D0%B8%D0%B5%D0%BD%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%BD%D1%8B%D0%B9_%D1%8F%D0%B7%D1%8B%D0%BA) для построения регулярных выражений в JavaScript. DSL следует подходу **data-first**: шаблон задаётся данными — декларативной схемой типа [`Schema`](#21-schema) — и преобразуется реализацией в объект [`RegExp`](https://developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Global_Objects/RegExp).

Схема сериализуема и может быть задана в коде либо получена из внешнего источника. Схемы являются альтернативой записи регулярных выражений в виде литералов.

<!--Спецификация определяет инструменты `createRegExp` и `sanitizeSchema` для работы со схемами, а также структуру самих схем. -->

> [!NOTE]
> Для эффективного использования данной спецификации рекомендуется понимать термины и принципы работы регулярных выражений, так как схемы описывают те же концепции в декларативном формате.

## Нормативные обозначения

Слова «ДОЛЖЕН» (MUST), «НЕ ДОЛЖЕН» (MUST NOT), «ОБЯЗАТЕЛЬНО» (REQUIRED), «СЛЕДУЕТ» (SHOULD), «НЕ СЛЕДУЕТ» (SHOULD NOT), «РЕКОМЕНДОВАННЫЙ» (RECOMMENDED), «МОЖЕТ» (MAY) и «НЕОБЯЗАТЕЛЬНЫЙ» (OPTIONAL) в этом документе должны быть интерпретированы в соответствии с [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

Инварианты схемы (допустимая форма данных) формулируются через «ДОЛЖЕН» и «НЕ ДОЛЖЕН».

## 1. Термины

### 1.1. Схема

Схема — это массив (секвенсор) объектов (атомов), описывающий структуру регулярного выражения в декларативном формате. Каждый элемент схемы (атом) представляет один логический шаг шаблона.

**Простой пример:**

```javascript
const schema = [
  { lineStart: true },
  {
    zeroOrMore: [
      { charIn: 'a-z' },
    ],
  },
  { lineEnd: true },
];
// Результат: /^(?:[a-z])*$/
```

**Пример: валидация email адреса**

Регулярное выражение:

```javascript
/^(?:[a-zA-Z0-9.!#$%&'*+\/=?^_`{|}~-])+@[a-zA-Z0-9](?:(?:[a-zA-Z0-9-]){0,61}[a-zA-Z0-9])?
(?:\.[a-zA-Z0-9](?:(?:[a-zA-Z0-9-]){0,61}[a-zA-Z0-9])?)+$/
```

Данное регулярное выражение проверяет корректность email адреса согласно стандарту RFC 5322.

Схема, описывающая это регулярное выражение:

```javascript
const schema = [
  { lineStart: true },
  // ^
  {
    repeat: [
      // (?: ... )+
      { charIn: "a-zA-Z0-9.!#$%&'*+/=?^_`{|}~-" },
      // [a-zA-Z0-9.!#$%&'*+/=?^_`{|}~-]
    ],
  },
  { exactly: '@' },
  // @
  { charIn: 'a-zA-Z0-9' },
  // [a-zA-Z0-9]
  {
    maybe: [
      // (?: ... )?
      {
        repeat: [
          // (?: ... ){0,61}
          { charIn: 'a-zA-Z0-9-' },
          // [a-zA-Z0-9-]
          { params: { times: [0, 61] } },
        ],
      },
      { charIn: 'a-zA-Z0-9' },
      // [a-zA-Z0-9]
    ],
  },
  {
    repeat: [
      // (?: ... )+
      { exactly: '.' },
      // .
      { charIn: 'a-zA-Z0-9' },
      // [a-zA-Z0-9]
      {
        maybe: [
          // (?: ... )?
          {
            repeat: [
              // (?: ... ){0,61}
              { charIn: 'a-zA-Z0-9-' },
              // [a-zA-Z0-9-]
              { params: { times: [0, 61] } },
            ],
          },
          { charIn: 'a-zA-Z0-9' },
          // [a-zA-Z0-9]
        ],
      },
    ],
  },
  { lineEnd: true },
  // $
];
```

### 1.2. Атом

Атом — это минимальная единица схемы, описывающая один логический шаг шаблона
(якорь, символьный класс, квантифицированную последовательность, альтернацию и т.п.).

Атом представляет собой объект с ровно одним ключом, который определяет тип шага.
Значением этого ключа может быть только:

- строка;
- число;
- булево значение;
- массив атомов (секвенсор) или, в случае [`anyOf`](#331-anyof), массив анонимных секвенсоров.

Значением атома не может быть другой атом или произвольный объект.

Любой объект, встречающийся в схеме, трактуется как атом,
**кроме специального объекта параметров `params`, который не считается атомом
и не описывает отдельный шаг шаблона** (см. [Объект параметров `params`](#15-объект-параметров-params)).

### 1.3. Секвенсор

Секвенсор — это массив атомов, объединяющий несколько подшаблонов в последовательность.
Порядок атомов в секвенсоре соответствует их порядку в итоговом регулярном выражении.

**Типы секвенсоров**
В схеме существует два типа секвенсоров, различающихся по контексту и допустимому содержимому:

- Атом‑секвенсор — атом, значением которого является секвенсор (см. [Атом‑секвенсор](#14-атомсеквенсор)).

- Анонимный секвенсор — секвенсор без атома‑обёртки: у него нет собственного ключа.
  Содержит **только атомы**; объект [`params`](#15-объект-параметров-params) в анонимном секвенсоре НЕ ДОЛЖЕН присутствовать.
  К анонимным секвенсорам относятся:
  - корневой секвенсор — верхнеуровневый массив схемы;
  - ветвь альтернативы — встречается только внутри атома‑секвенсора [`anyOf`](#331-anyof) и описывает одну ветвь альтернативы.

### 1.4. Атом‑секвенсор

**Атом‑секвенсор** — это атом, значением которого является секвенсор (массив атомов) или, для [`anyOf`](#331-anyof), массив анонимных секвенсоров.
Описывает последовательность подшаблонов: вложенные атомы интерпретируются в порядке следования в массиве и соответствуют конкатенации подшаблонов внутри одной группирующей конструкции.

Атом‑секвенсор всегда выступает как обёртка над подшаблонами, эквивалентная одной из групп регулярного выражения:

- не захватывающая `(?: … )`
- захватывающая `( … )`
- именованная `(?<name> … )`

По умолчанию атом‑секвенсор создаёт **не захватывающую** группу `(?: … )` в качестве обёртки (кроме [`grouped`](#321-grouped)).
Тип обёртки можно изменить с помощью параметра [`group`](#group) в объекте параметров `params`.

[**Атомы‑секвенсоры:**](#3-атомы-секвенсоры)

- [`repeat`](#311-repeat)
- [`zeroOrMore`](#312-zeroormore)
- [`maybe`](#313-maybe)
- [`grouped`](#321-grouped)
- [`anyOf`](#331-anyof)

### 1.5. Объект параметров `params`

**Объект параметров `params`** задаёт параметры атома‑секвенсора, внутри которого расположен.
`params` не считается атомом схемы, не участвует в последовательности подшаблонов и не влияет на порядок исполнения вложенных атомов.
Объект `params` ДОЛЖЕН находиться **в конце** массива атома‑секвенсора и интерпретируется как метаданные этого атома‑секвенсора.

#### Контекст использования

Объект `params` ДОЛЖЕН находиться **только** внутри атомов‑секвенсоров (см. также [Секвенсор](#13-секвенсор)).

<a id="times"></a>

#### Параметр `times`

Задаёт точное количество повторений или диапазон.

Применяется **_только_** к квантификатору [`repeat`](#311-repeat).

```typescript
times?: number | [number] | [number, number];
```

| Значение     | Эквивалент  | Описание                                         |
| ------------ | ----------- | ------------------------------------------------ |
| `n`          | `{n}`       | ровно `n` повторений                             |
| `[min]`      | `{min,}`    | одноэлементный кортеж: от `min` до бесконечности |
| `[min, max]` | `{min,max}` | двухэлементный кортеж: диапазон повторений       |

Все числа в `times` (`n`, `min`, `max`) ДОЛЖНЫ быть **целыми неотрицательными** (≥ 0).
Для двухэлементного кортежа `[min, max]` ДОЛЖНО выполняться условие `min ≤ max`.

> Если параметр `times` не указан, используется квантификатор `+` (повторить 1 раз или больше).

<a id="lazy"></a>

#### Параметр `lazy`

Флаг ленивого квантификатора.

Значение `true` — делает квантификатор ленивым (`*?`, `??`, `{n,}?`), значение `false` отключает флаг. Применяется ко всем квантификаторам: [`repeat`](#311-repeat), [`zeroOrMore`](#312-zeroormore), [`maybe`](#313-maybe).

```typescript
lazy?: boolean;
```

<a id="group"></a>

#### Параметр `group`

Определяет тип группирующей конструкции:

- `false`: не захватывающая группа `(?: … )`
- `true`: захватывающая группа `( … )`
- `"<name>"`: именованная группа `(?<name> … )`

Если `group` — строка, она ДОЛЖНА быть [валидным именем захватывающей группы](#valid-capture-group-name).

```typescript
group?: boolean | string;
```

<a id="valid-capture-group-name"></a>

##### Валидное имя захватывающей группы

Имя именованной захватывающей группы ДОЛЖНО соответствовать грамматике [`IdentifierName`](https://tc39.es/ecma262/#prod-IdentifierName) спецификации ECMAScript.

Практические ограничения:

- имя НЕ ДОЛЖНО быть пустой строкой
- имя НЕ ДОЛЖНО начинаться с цифры (`0`–`9`)
- первый символ ДОЛЖЕН соответствовать грамматике [`IdentifierStart`](https://tc39.es/ecma262/#prod-IdentifierStart)
- каждый последующий символ ДОЛЖЕН соответствовать грамматике [`IdentifierPart`](https://tc39.es/ecma262/#prod-IdentifierPart)

Допустимый ASCII‑поднабор: `[A-Za-z_$][A-Za-z0-9_$]*`.

Невалидные примеры: `""`, `"1name"`, `"my-name"`, `"a b"`.

<a id="optionally"></a>

#### Параметр `optionally`

Флаг, делающий группу необязательной.

Применяется **_только_** к альтернации [`anyOf`](#331-anyof).

```typescript
optionally?: boolean;
```

#### Соотношение параметров и атомов-секвенсоров

| Параметр     | Атом-секвенсор                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `times`      | [`repeat`](#311-repeat)                                                                                                           |
| `lazy`       | [`repeat`](#311-repeat), [`zeroOrMore`](#312-zeroormore), [`maybe`](#313-maybe)                                                   |
| `group`      | [`repeat`](#311-repeat), [`zeroOrMore`](#312-zeroormore), [`maybe`](#313-maybe), [`grouped`](#321-grouped), [`anyOf`](#331-anyof) |
| `optionally` | [`anyOf`](#331-anyof)                                                                                                             |

## 2. Типы

Данный раздел описывает типы TypeScript для работы со схемами.

### 2.1. `Schema`

Тип схемы — корневой (анонимный) секвенсор, содержащий только атомы.

```typescript
type Schema = Atom[];
```

### 2.2. `Atom`

Атом — минимальная единица схемы. Объединение всех типов атомов.

```typescript
type Atom = BooleanAtom | StringAtom | ReferenceToAtom | AtomSequencer;

type BooleanAtom =
  | { lineStart: boolean }
  | { lineEnd: boolean }
  | { digit: boolean }
  | { word: boolean }
  | { whitespace: boolean }
  | { boundary: boolean }
  | { anyChar: boolean }
  | { tab: boolean }
  | { lineFeed: boolean }
  | { carriageReturn: boolean };

type StringAtom =
  | { exactly: string }
  | { charIn: string }
  | { charNotIn: string }
  | { unicodeProps: string };

type ReferenceToAtom = { referenceTo: number | string };
```

### 2.3. `AtomSequencer`

Атомы‑секвенсоры, принимающие секвенсор (или, для [`anyOf`](#331-anyof), массив анонимных секвенсоров) с соответствующими типами параметров.

```typescript
type AtomSequencer =
  | { repeat: RepeatSequence }
  | { zeroOrMore: ZeroOrMoreSequence }
  | { maybe: MaybeSequence }
  | { grouped: GroupedSequence }
  | { anyOf: AnyOfSequence };

// params — последний элемент массива, если задан
type RepeatSequence =
  | Atom[]
  | [...Atom[], { params: RepeatParams }];

type ZeroOrMoreSequence =
  | Atom[]
  | [...Atom[], { params: ZeroOrMoreParams }];

type MaybeSequence =
  | Atom[]
  | [...Atom[], { params: MaybeParams }];

type GroupedSequence =
  | Atom[]
  | [...Atom[], { params: GroupedParams }];

type AnyOfSequence =
  | Atom[][]
  | [...Atom[][], { params: AnyOfParams }];
```

### 2.4. `Params`

Типы параметров для атомов‑секвенсоров. Каждый атом‑секвенсор имеет свой набор допустимых параметров.

```typescript
type Params =
  | RepeatParams
  | ZeroOrMoreParams
  | MaybeParams
  | GroupedParams
  | AnyOfParams;

type RepeatParams = {
  times?: number | [number] | [number, number];
  lazy?: boolean;
  group?: boolean | string;
};

type ZeroOrMoreParams = {
  lazy?: boolean;
  group?: boolean | string;
};

type MaybeParams = {
  lazy?: boolean;
  group?: boolean | string;
};

type GroupedParams = {
  group?: boolean | string;
};

type AnyOfParams = {
  group?: boolean | string;
  optionally?: boolean;
};
```

## 3. Атомы-секвенсоры

### 3.1. _Квантификаторы_

### 3.1.1. `repeat`

- Тип: [AtomSequencer](#23-atomsequencer)
- Эквивалент: `{n}`, `{min,max}`, `{min,}`, `+`

**`repeat`** — Создаёт группу с квантификатором повторения.
Объединяет подшаблоны и позволяет повторять их с заданной кратностью.

#### Поддерживаемые параметры

Объект `params` может содержать (см. [Объект параметров `params`](#15-объект-параметров-params)):

- [`times`](#times) — без параметра эквивалентно `+` (1 раз или больше);
- [`lazy`](#lazy) — по умолчанию `false`;
- [`group`](#group) — по умолчанию `false` (не захватывающая группа `(?: … )`).

#### Примеры

```javascript
const schema = [
  {
    repeat: [
      { charIn: 'a-z' },
      {
        params: {
          times: [0, 3],
          lazy: true,
        },
      },
    ],
  },
];
// Результат: /(?:[a-z]){0,3}?/

const schema = [
  {
    repeat: [
      { exactly: 'foo' },
      { params: { group: 'word' } },
    ],
  },
];
// Результат: /(?<word>foo)+/
```

### 3.1.2. `zeroOrMore`

- Тип: [AtomSequencer](#23-atomsequencer)
- Эквивалент: `*`

**`zeroOrMore`** — Создаёт группу с квантификатором `*`.
Повторяет подшаблон **ноль или более раз**.

#### Поддерживаемые параметры

Объект `params` может содержать (см. [Объект параметров `params`](#15-объект-параметров-params)):

- [`lazy`](#lazy) — по умолчанию `false`;
- [`group`](#group) — по умолчанию `false` (не захватывающая группа `(?: … )`).

#### Примеры

```javascript
const schema = [
  {
    zeroOrMore: [
      { exactly: 'foo' },
    ],
  },
];
// Результат: /(?:foo)*/

const schema = [
  {
    zeroOrMore: [
      { charIn: 'a-z' },
      { params: { group: 'letters', lazy: true } },
    ],
  },
];
// Результат: /(?<letters>[a-z])*?/
```

### 3.1.3. `maybe`

- Тип: [AtomSequencer](#23-atomsequencer)
- Эквивалент: `?`

**`maybe`** — Создаёт группу с квантификатором `?` (повторить подшаблон **ноль или один раз**).
Делает подшаблон **необязательным**.

#### Поддерживаемые параметры

Объект `params` может содержать (см. [Объект параметров `params`](#15-объект-параметров-params)):

- [`lazy`](#lazy) — по умолчанию `false`;
- [`group`](#group) — по умолчанию `false` (не захватывающая группа `(?: … )`).

#### Примеры

```javascript
const schema = [
  {
    maybe: [
      { exactly: 'foo' },
    ],
  },
];
// Результат: /(?:foo)?/

const schema = [
  {
    maybe: [
      { charIn: 'A-Z' },
      { params: { group: 'opt', lazy: true } },
    ],
  },
];
// Результат: /(?<opt>[A-Z])??/
```

---

### 3.2. _Группа_

### 3.2.1. `grouped`

- Тип: [AtomSequencer](#23-atomsequencer)
- Эквивалент: `(...)`, `(?:...)`, `(?<name>...)`

**`grouped`** — Создаёт группирующую конструкцию.
Объединяет несколько подшаблонов в одну логическую группу.

#### Поддерживаемые параметры

Объект `params` может содержать (см. [Объект параметров `params`](#15-объект-параметров-params)):

- [`group`](#group) — по умолчанию `true` (захватывающая группа `( … )`).

#### Примеры

```javascript
const schema = [
  {
    grouped: [
      { exactly: 'foo' },
      { charIn: 'A-Z' },
    ],
  },
];
// Результат: /(foo[A-Z])/

const schema = [
  {
    grouped: [
      { exactly: 'bar' },
      { params: { group: false } },
    ],
  },
];
// Результат: /(?:bar)/

const schema = [
  {
    grouped: [
      { exactly: 'buzz' },
      { params: { group: 'word' } },
    ],
  },
];
// Результат: /(?<word>buzz)/
```

---

### 3.3. _Альтернация_

### 3.3.1. `anyOf`

- Тип: [AtomSequencer](#23-atomsequencer)
- Эквивалент: `|`

**`anyOf`** — Создаёт **альтернацию** (_оператор выбора_).
Объединяет несколько ветвей альтернативы, из которых должна совпасть хотя бы одна.

#### Структура

Значением ключа `anyOf` является массив анонимных секвенсоров (ветвей альтернативы).
Объект `params`, если задан, относится ко всему `anyOf` и ДОЛЖЕН стоять **последним** элементом внешнего массива (см. [Объект параметров `params`](#15-объект-параметров-params)).

```javascript
{
  anyOf: [
    [ /* ветвь 1 */ ],
    [ /* ветвь 2 */ ],
    // { params: { … } } — на уровне anyOf, не внутри ветвей
  ]
}
```

#### Поддерживаемые параметры

Объект `params` может содержать (см. [Объект параметров `params`](#15-объект-параметров-params)):

- [`group`](#group) — по умолчанию `false` (не захватывающая группа `(?: … )`);
- [`optionally`](#optionally) — по умолчанию `false`.

> [!NOTE]
>
> РЕКОМЕНДУЕТСЯ использовать параметр [`optionally`](#optionally) вместо оборачивания `anyOf` в [`maybe`](#313-maybe), чтобы избежать излишней вложенности.

#### Примеры

```javascript
const schema = [
  {
    anyOf: [
      [
        { charIn: '01' },
        { digit: true },
      ], // ветвь 1
      [
        { exactly: '2' },
        { charIn: '0-3' },
      ], // ветвь 2
      { params: { group: 'hours' } },
    ],
  },
  { exactly: ':' },
  {
    grouped: [
      { charIn: '0-5' },
      { digit: true },
      { params: { group: 'minutes' } },
    ],
  },
];
// Результат: /(?<hours>[01]\d|2[0-3]):(?<minutes>[0-5]\d)/

const str = '23:59 25:99 1:2';
const re = /(?<hours>[01]\d|2[0-3]):(?<minutes>[0-5]\d)/;
const result = str.match(re);

console.log(result);

/* Вывод:
[
  '23:59',
  '23',
  '59',
  index: 0,
  input: '23:59 25:99 1:2',
  groups: [Object: null prototype] { hours: '23', minutes: '59' }
]
*/
```

## 4. Атомы

### 4.1. _Утверждения_

### 4.1.1. `lineStart`

- Тип: [Atom](#22-atom)
- Эквивалент: `^`

**`lineStart`** — Якорь начала строки.

Принимает булево значение: `true` активирует якорь, `false` игнорирует атом.

Если атом `lineStart` присутствует в схеме, он ДОЛЖЕН быть первым элементом корневого секвенсора.

```javascript
{
  lineStart: true
} // ^
```

### 4.1.2. `lineEnd`

- Тип: [Atom](#22-atom)
- Эквивалент: `$`

**`lineEnd`** — Якорь конца строки.

Принимает булево значение: `true` активирует якорь, `false` игнорирует атом.

Если атом `lineEnd` присутствует в схеме, он ДОЛЖЕН быть последним элементом корневого секвенсора.

```javascript
{
  lineEnd: true
} // $
```

### 4.1.3. `boundary`

- Тип: [Atom](#22-atom)
- Эквивалент: `\b`, `\B`

**`boundary`** — Утверждение границы слова.

Принимает булево значение: `true` сопоставляет границу слова, `false` сопоставляет позицию, не являющуюся границей слова.

```javascript
{
  boundary: true
} // \b
{
  boundary: false
} // \B
```

---

### 4.2. _Литералы и экранирования символов_

### 4.2.1. `exactly`

- Тип: [Atom](#22-atom)

**`exactly`** — Сопоставляет точную последовательность символов (литерал).

Принимает строку, которая будет экранирована и использована как есть в регулярном выражении.

```javascript
{
  exactly: 'foo'
} // foo
{
  exactly: '.'
} // \.
{
  exactly: '('
} // \(
```

### 4.2.2. `anyChar`

- Тип: [Atom](#22-atom)
- Эквивалент: `.`

**`anyChar`** — Сопоставляет любой символ, кроме символов новой строки.

```javascript
{
  anyChar: true
} // .
```

### 4.2.3. `tab`

- Тип: [Atom](#22-atom)
- Эквивалент: `\t`

**`tab`** — Символ табуляции.

```javascript
{
  tab: true
} // \t
```

### 4.2.4. `lineFeed`

- Тип: [Atom](#22-atom)
- Эквивалент: `\n`

**`lineFeed`** — Символ перевода строки.

```javascript
{
  lineFeed: true
} // \n
```

### 4.2.5. `carriageReturn`

- Тип: [Atom](#22-atom)
- Эквивалент: `\r`

**`carriageReturn`** — Символ возврата каретки.

```javascript
{
  carriageReturn: true
} // \r
```

### 4.3. _Символьные классы и экранирования Unicode-свойств_

### 4.3.1. `charIn`

- Тип: [Atom](#22-atom)
- Эквивалент: `[ ... ]`

**`charIn`** — Символьный класс, сопоставляющий любой символ из указанного набора.

Принимает строку, описывающую набор символов в формате, аналогичном символьным классам регулярных выражений (диапазоны, экранированные символы и т.п.).

```javascript
{
  charIn: 'a-z'
} // [a-z]
{
  charIn: 'a-zA-Z0-9'
} // [a-zA-Z0-9]
{
  charIn: 'abc'
} // [abc]
```

### 4.3.2. `charNotIn`

- Тип: [Atom](#22-atom)
- Эквивалент: `[^ ...]`

**`charNotIn`** — Отрицательный символьный класс, сопоставляющий любой символ, **не** входящий в указанный набор.

Принимает строку, описывающую набор символов в формате, аналогичном символьным классам регулярных выражений.

```javascript
{
  charNotIn: 'a-z'
} // [^a-z]
{
  charNotIn: '0-9'
} // [^0-9]
```

### 4.3.3. `unicodeProps`

- Тип: [Atom](#22-atom)
- Эквивалент: `\p{...}`

**`unicodeProps`** — Сопоставляет символы по Unicode-свойству.

Принимает строку. Допустимые значения — по правилам Unicode property escapes в JavaScript Flavor (см. [MDN: Unicode character class escape](https://developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Regular_expressions/Unicode_character_class_escape)).

Для построения `RegExp` по схеме, содержащей `unicodeProps`, [набор флагов](#52-флаги) ДОЛЖЕН содержать `u` или `v`. Если ни один из этих флагов не задан, построение НЕ ДОЛЖНО завершаться успехом.

```javascript
{
  unicodeProps: 'Letter'
} // \p{Letter}
{
  unicodeProps: 'Script=Latin'
} // \p{Script=Latin}
```

### 4.3.4. `digit`

- Тип: [Atom](#22-atom)
- Эквивалент: `\d`, `\D`

**`digit`** — Символьный класс, сопоставляющий десятичные цифры.

Принимает булево значение: `true` сопоставляет любую десятичную цифру (0-9), `false` сопоставляет любой символ, не являющийся десятичной цифрой.

```javascript
{
  digit: true
} // \d
{
  digit: false
} // \D
```

### 4.3.5. `word`

- Тип: [Atom](#22-atom)
- Эквивалент: `\w`, `\W`

**`word`** — Символьный класс, сопоставляющий символы слова.

Принимает булево значение: `true` сопоставляет латинские буквы (A-Z, a-z), десятичные цифры (0-9) и символ подчёркивания (`_`), `false` сопоставляет любой символ, не являющийся символом слова.

```javascript
{
  word: true
} // \w
{
  word: false
} // \W
```

### 4.3.6. `whitespace`

- Тип: [Atom](#22-atom)
- Эквивалент: `\s`, `\S`

**`whitespace`** — Символьный класс, сопоставляющий пробельные символы.

Принимает булево значение: `true` сопоставляет пробельные символы, `false` сопоставляет любой символ, не являющийся пробельным.

```javascript
{
  whitespace: true
} // \s
{
  whitespace: false
} // \S
```

### 4.4. _Обратные ссылки_

### 4.4.1. `referenceTo`

- Тип: [Atom](#22-atom)
- Эквивалент: `\k<name>`, `\N`

**`referenceTo`** — Обратная ссылка на захватывающую группу.

Значение ДОЛЖНО быть одним из:

- **число** `N` — обратная ссылка по номеру (`\N`);
- **строка** — обратная ссылка по имени (`\k<name>`).

Числовое значение `N` ДОЛЖНО быть целым и удовлетворять `1 ≤ N ≤ K`, где `K` — общее количество захватывающих групп в схеме, включая именованные. При `K = 0` атом `referenceTo` с числовым значением НЕ ДОЛЖЕН присутствовать в схеме.

Строковое значение ДОЛЖНО быть [валидным именем захватывающей группы](#valid-capture-group-name). В схеме ДОЛЖНА существовать именованная захватывающая группа с тем же значением параметра `group`.

JavaScript `RegExp` допускает обратную ссылку перед соответствующей захватывающей группой. До сопоставления группы такая ссылка считается совпавшей и не потребляет символы входной строки (см. [Backreference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Backreference)). Чтобы исключить это неочевидное поведение, соответствующая захватывающая группа ДОЛЖНА предшествовать атому `referenceTo` в схеме.

```javascript
{
  referenceTo: 1
} // \1
{
  referenceTo: 'name'
} // \k<name>
```

## 5. Построение `RegExp`

### 5.1. Входные данные

Входными данными построения являются:

- схема типа [`Schema`](#21-schema);
- набор флагов.

Набор флагов не является частью схемы. Способ представления и передачи набора флагов, а также имя и сигнатура функции построения настоящей спецификацией не нормируются.

Успешным результатом построения ДОЛЖЕН быть объект [`RegExp`](https://developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Global_Objects/RegExp).

### 5.2. Флаги

Каждый заданный флаг ДОЛЖЕН соответствовать одному из флагов JavaScript `RegExp`: `d`, `g`, `i`, `m`, `s`, `u`, `v` или `y`. Флаги `u` и `v` НЕ ДОЛЖНЫ использоваться одновременно.

Если набор флагов не задан, построенный `RegExp` НЕ ДОЛЖЕН содержать флаги.

Набор флагов построенного `RegExp` ДОЛЖЕН совпадать с заданным набором. Реализация НЕ ДОЛЖНА добавлять или удалять флаги на основании содержимого схемы.

Построение НЕ ДОЛЖНО завершаться успехом, если задан флаг вне указанного выше перечня, одновременно заданы `u` и `v` либо схема содержит `unicodeProps`, но не задан ни `u`, ни `v`.

## 6. Соответствие реализации

Реализация **соответствует** настоящей спецификации, если одновременно выполняются условия ниже.

### 6.1. Допустимые входные данные

Для любой схемы, удовлетворяющей инвариантам этой спецификации, и любого набора флагов, удовлетворяющего [требованиям к флагам](#52-флаги) и требованиям используемых атомов, соответствующая реализация ДОЛЖНА построить объект `RegExp`, семантика которого согласована с описанными эквивалентами атомов и атомов‑секвенсоров.

### 6.2. Нарушение требований

Входные данные ДОЛЖНЫ считаться невалидными, если схема нарушает любой инвариант настоящей спецификации либо набор флагов нарушает [требования к флагам](#52-флаги). В этом случае реализация:

- НЕ ДОЛЖНА возвращать объект `RegExp` как успешный результат построения;
- НЕ ДОЛЖНА предпринимать скрытую нормализацию (sanitize) входных данных ради успешного построения `RegExp`;
- ДОЛЖНА сообщить об ошибке.

Конкретный механизм сообщения об ошибке этой спецификацией не нормируется.

### 6.3. Расширения

Реализация МОЖЕТ поддерживать дополнительные атомы, параметры или формы сверх описанных здесь.
Поведение таких расширений настоящей спецификацией не нормируется; на схемы, использующие только конструкции из этого документа, требования разделов 6.1 и 6.2 распространяются в полном объёме.
